# Наблюдатель за howborisusesclaudecode.com

Следит за сайтом и присылает в Telegram готовый разбор на русском, когда там появляется новое. Не ссылку и не пересказ — объяснение: что это, как работает по сути, работает ли на Windows, что делать и стоит ли оно твоего времени.

Смысл в том, чтобы не заходить на сайт вообще.

## Как это устроено за минуту

```
GitHub Actions (cron, раз в 6 часов)
  │
  ├─ условный GET → 304? выходим, потрачено 0
  ├─ хеш контента не изменился? выходим, потрачено 0
  ├─ проверки целостности → сломались? алерт, состояние не трогаем
  ├─ диф по блокам → список конкретных событий
  ├─ фильтр по журналу доставок → что уже отправляли, не отправляем
  │
  ├─ на КАЖДОЕ событие: контекст → модель → разбор → Telegram → журнал (push)
  │
  ├─ всё доставлено? двигаем снапшот
  └─ прогон чистый? пингуем внешний watchdog
```

Ключевая идея: **что именно изменилось — решает код, а не модель.** Диф детерминированный. Модель получает готовое событие и отвечает только на «что это значит и правда ли это». Это убирает целый класс галлюцинаций и делает вход в восемь раз дешевле.

## Два инварианта, из которых следует почти всё

**1. Снапшот двигается вперёд ровно тогда, когда все события прогона доставлены.**
Отсюда бесплатно получается идемпотентный ретрай: недоставленное повторится само, а журнал отфильтрует уже отправленное. Поэтому в системе нет очереди — она добавила бы то, что уже работает.

**2. Пинг внешнему watchdog уходит только после чистого прогона.**
Внутренний отказ становится внешне видимым. Упавший или незапустившийся процесс не может сообщить о своей смерти сам — молчание пинга сообщает за него.

## Состояние

Живёт в git, в `state/`. Это одновременно хранилище, история и инструмент отладки:

```bash
git diff HEAD~1 state/snapshot.json     # что система сочла изменением
git checkout HEAD~1 -- state/snapshot.json  # вся процедура восстановления
```

| Файл | Долговечность | Почему так |
|---|---|---|
| `delivered.json` | push после **каждой** доставки | раннер эфемерный; незапушенный журнал = потерянный журнал = дубли |
| `snapshot.json` | push один раз в конце, только при полной доставке | это и есть инвариант №1 |
| `heartbeat.json` | push не чаще раза в 20 часов | GitHub отключает scheduled workflow после 60 дней без активности |
| `last_raw.html.gz` | каждый прогон | вскрытие сломанного парсера офлайн |

## Настройка

Нужно три вещи снаружи: бот в Telegram, ключ Anthropic и проверка на healthchecks.io.

```bash
# 1. Бот: напиши @BotFather -> /newbot -> получи токен
# 2. Напиши своему боту любое сообщение (бот не может написать первым)
# 3. Узнай chat_id:
python tools/setup.py chat-id

# 4. Проверка на healthchecks.io: период 6 часов, grace 20 часов,
#    канал — Telegram-интеграция + email (email обязателен: если лежит
#    именно Telegram, телеграмное уведомление о смерти не дойдёт)

# 5. Залей секреты (ввод интерактивный, ничего не попадает в argv и историю):
python tools/setup.py secrets

# 6. Проверь, что всё на месте:
python tools/setup.py check

# 7. Запиши базовую линию БЕЗ рассылки 127 разборов:
gh workflow run watch.yml -f bootstrap=true
```

После этого система работает сама. Новостей нет — сообщений нет.

## Инструменты

```bash
# Что реально распарсилось (калибровка парсера)
python tools/inspect_site.py
python tools/inspect_site.py --part 22 --full

# Порог сопоставления блоков: как классифицируется правка растущего размера
python tools/replay.py --sweep 22:1

# Канонические сценарии обнаружения на реальных данных
python tools/replay.py --scenario edit|add|delete|move|newpart
```

`replay.py` — не украшение. Он нашёл, что `difflib.SequenceMatcher` при длине строки >200 включает эвристику `autojunk` и объявляет мусором всё, что встречается чаще чем в 1% символов. На тексте совета это пробелы и частые буквы. Правка 5% слов давала `ratio 0.36` вместо `0.95`, то есть **каждая реальная правка приезжала бы как «удалили + добавили»** — и тесты на коротких строках этого не показывали. Прогоняй `--sweep` после каждой правки матчинга.

## Что делать, когда сломается

| Симптом | Что произошло | Действие |
|---|---|---|
| Алерт «парсер не смог разобрать» | сайт перевёрстан | `python tools/inspect_site.py --file state/last_raw.html.gz`, чинить `source.py` |
| Алерт «проверки целостности не прошли» | структура поехала | там же указано, в какой части и на сколько разошлось |
| Алерт «слишком масштабное изменение» | перевёрстка под видом правок | посмотреть диф, при необходимости поднять порог в конфиге |
| Алерт «состояние повреждено» | обрезанный JSON | `git checkout HEAD~1 -- state/snapshot.json` |
| healthchecks молчит про смерть, но и разборов нет | всё в порядке, новостей нет | ничего |
| healthchecks прислал «оно умерло» | задача не запускается | проверить, не отключён ли workflow, и вкладку Actions |

## Стоимость

Около **$0.60 в месяц** до 31.08.2026 (вводная цена Sonnet 5 $2/$10 за MTok), около **$0.90** после. Плохой месяц с дюжиной событий — $1.8 и $2.6 соответственно.

GitHub Actions, healthchecks.io и Telegram — бесплатно в используемых объёмах: ~90 минут из 2000 бесплатных в месяц.

Отдельно платный только `web_search` — $10 за 1000 поисков, поэтому в конфиге стоит потолок `web_search_max_uses`. `web_fetch` бесплатен, но у него стоит `max_content_tokens`: страница на 500 КБ это ~125k токенов входа.
